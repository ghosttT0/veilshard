vpnctl 开发设计文档 v0.1
1. 项目定位
1.1 项目名称
暂定：
vpnctl

后续可以重新取正式项目名。
1.2 项目目标
vpnctl 是一个使用 Go 编写的单二进制 VPS 私人代理部署与管理工具。
用户只需要：
sudo vpnctl install

即可完成：
环境检测
   ↓
安全检查
   ↓
安装 Proxy Core
   ↓
生成身份凭据
   ↓
生成服务端配置
   ↓
配置 systemd
   ↓
配置 UFW
   ↓
启动服务
   ↓
Health Check
   ↓
生成 Mihomo 配置

第一阶段：
不重新实现代理协议。

数据平面交给经过广泛使用的成熟 Core。
vpnctl 负责的是 Control Plane / Management Plane。

7. SSH 自动检测
这是一个非常重要的安全功能。
禁止假定：
SSH = 22

例如我们现在测试的 VPS：
SSH = 62505

程序应该读取：
/etc/ssh/sshd_config
/etc/ssh/sshd_config.d/*

同时检查实际监听：
/proc

或通过系统接口获取 socket 状态。
最终：
Detected SSH:

TCP/62505

在任何 firewall 操作之前：
ALLOW 62505/tcp

必须已经存在。
8. Firewall Transaction
绝对不能简单：
ufw reset

也不能修改用户已有规则。
原则：
只管理 vpnctl 自己创建的规则。

例如：
62505/tcp    ALLOW    # existing SSH

443/tcp      ALLOW    # vpnctl:proxy

卸载时：
只删除 vpnctl:proxy

而：
62505

保持不变。
9. Transaction / Rollback
安装必须是事务性的。
例如：
Snapshot
   ↓
Install binary
   ↓
Generate config
   ↓
Install systemd
   ↓
Firewall
   ↓
Start
   ↓
Health Check

如果：
Health Check FAILED

则：
Rollback
   ↓
restore firewall
restore config
restore systemd
remove incomplete files

最终：
Installation failed.

Rollback:
✓ Firewall restored
✓ Service removed
✓ Previous configuration restored

System returned to previous state.

这会成为我们相对于普通 shell 一键脚本非常大的优势。

11. Core 权限
不建议：
root
 ↓
Proxy Core

长期运行。
创建：
vpnctl-proxy

system user：
shell: /usr/sbin/nologin
home: none

Core 尽量：
vpnctl-proxy

运行。
12. systemd Hardening
生成：
/etc/systemd/system/vpnctl-proxy.service

除了基本启动配置，加入适合 Core 的 systemd sandboxing，例如根据实际兼容性测试：
NoNewPrivileges=true
PrivateTmp=true
ProtectHome=true
ProtectSystem=strict
ProtectKernelTunables=true
ProtectKernelModules=true
ProtectControlGroups=true
RestrictSUIDSGID=true

不能为了“看起来安全”一次把所有限制打开。
必须：
enable
→ test
→ document

因为部分 Core 功能可能确实需要特定系统能力。
13. 凭据生成
所有秘密必须在 VPS 本地生成。
例如：
UUID
X25519 Private Key
X25519 Public Key
Short ID

随机源：
crypto/rand

禁止：
math/rand

禁止：
硬编码 UUID
默认 password
固定 short ID

14. Secret Handling
CLI 默认不能直接：
vpnctl status

然后把所有 Private Key 打到终端。
例如：
Proxy: Running
Protocol: VLESS Reality
Port: 443
Users: 1

Private key:
********

只有明确：
vpnctl export mihomo

才输出客户端所需信息。
服务端 Private Key 永远不应该进入客户端配置。
15. 用户模型
即使 v0.1 主要自己用，也不要把架构写死成单用户。
例如：
type User struct {
    ID        string
    Name      string
    UUID      string
    Enabled   bool
    CreatedAt time.Time
}

CLI：
vpnctl user list

NAME        STATUS
my-pc       enabled
iphone      enabled
ipad        disabled

添加：
vpnctl user add iphone

删除：
vpnctl user remove iphone

16. Mihomo Export
这是我们项目非常重要的功能。
执行：
vpnctl export mihomo

输出可直接放入 Mihomo 的节点定义。
类似：
proxies:
  - name: US-VPS
    type: vless
    server: <SERVER>
    port: 443
    uuid: <UUID>
    network: tcp
    tls: true
    reality-opts:
      public-key: <PUBLIC_KEY>
      short-id: <SHORT_ID>

实际字段必须根据对应版本的 Mihomo schema 生成，不能凭模板长期写死。

20. Doctor 不应该自动乱修
例如发现：
WARN
SSH permits password authentication.

不要偷偷修改：
sshd_config

只告诉用户：
Recommendation:
Consider SSH key authentication.

Run:
vpnctl doctor --explain SSH001

如果以后做：
vpnctl doctor --fix

也必须明确列出准备修改的内容并获得确认。

23. Uninstall
执行：
sudo vpnctl uninstall

不能粗暴删除。
先显示：
Will remove:

vpnctl proxy service
proxy core
TCP/443 firewall rule
vpnctl configuration

Will NOT modify:

SSH
existing UFW rules
Docker
other services

确认以后才执行。
并允许：
vpnctl uninstall --keep-config

24. 配置文件
例如：
version: 1

server:
  port: 443

core:
  provider: xray

protocol:
  type: vless-reality

firewall:
  provider: ufw

security:
  run_as_user: vpnctl-proxy

export:
  default_client: mihomo

注意：
配置描述“用户想要的状态”，state 描述“vpnctl 实际做过什么”。

两个不能混在一起。
25. State 文件
例如：
{
  "schema_version": 1,
  "installed": true,
  "managed_firewall_rules": [
    "443/tcp"
  ],
  "core_version": "x.x.x",
  "service_name": "vpnctl-proxy"
}

这样 uninstall 才知道：
哪些东西是我创建的？

而不是猜。

27. Core abstraction
这一点现在就应该设计。
例如：
type Core interface {
    Install(ctx context.Context) error
    GenerateConfig(ctx context.Context, cfg Config) error
    Validate(ctx context.Context) error
    Start(ctx context.Context) error
    Stop(ctx context.Context) error
    Version(ctx context.Context) (string, error)
}

这样第一版：
Core
 └── Xray

以后可以：
Core
 ├── Xray
 └── sing-box

上层：
install
doctor
export
update

基本不用推倒重写。
